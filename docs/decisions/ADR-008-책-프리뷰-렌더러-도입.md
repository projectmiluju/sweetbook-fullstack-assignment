# ADR-008: SweetBook 템플릿 레이아웃 기반 책 프리뷰 렌더러 도입

**일자:** 2026-04-08
**상태:** Accepted

## 맥락 (Context)

SweetBook sandbox API는 생성된 책의 프리뷰(PDF, 이미지)를 제공하지 않는다. `GET /books/{bookUid}/preview`, `/pdf`, `/pages` 엔드포인트 모두 404를 반환하며, 책 목록의 `pdfStatus`도 null이다. 프로덕션 환경에서 프리뷰가 되는지는 확인할 수 없다 (sandbox 제한일 수도, API 자체 미지원일 수도 있음).

내지 콘텐츠 매핑을 개선해도 결과물을 시연에서 보여줄 수 없으면 효과를 증명할 수 없다.

한편, SweetBook 템플릿 API(`GET /templates/{uid}`)는 각 요소의 절대 좌표(x, y), 크기(width, height), 폰트, 색상, 텍스트 정렬 등 **레이아웃 데이터를 모두 제공**한다.

## 고려한 선택지

### 선택지 A: 템플릿 레이아웃 기반 HTML/CSS 렌더링 (정밀)

- 장점: 실제 인쇄 결과와 유사한 프리뷰. 시연 시 "실제 책과 동일한 프리뷰"라고 말할 수 있음. API에서 좌표·폰트 데이터를 이미 제공하므로 추측이 아닌 데이터 기반
- 단점: 구현 비용이 높음(L). 그래픽 리소스 접근 불가 시 fallback 필요. 100% 정확한 인쇄 교정(proof)은 아님

### 선택지 B: 자체 디자인 카드 UI (간소)

- 장점: 구현 비용 낮음(M). SweetBook 템플릿과 무관하게 자유 디자인
- 단점: 실제 책과 전혀 다른 모습. "이런 내용이 들어갑니다" 수준에 그침. 시연 임팩트 낮음

## 결정 (Decision)

**선택지 A 채택.**

- SweetBook 템플릿의 `layout.elements` 좌표를 HTML/CSS `position: absolute`로 1:1 변환
- 페이지 치수: 864 x 1212 (내지a의 bg-taupe 폭 864, divider 높이 1212에서 역산)
- 컨테이너 크기에 맞춰 `scale = containerWidth / 864`로 축소 렌더링
- 템플릿 데이터는 빌드 타임에 정적 저장 (API key 프론트 노출 방지 + 지연 제거)
- 사용 폰트: NanumMyeongjo, DM Serif Display, Do Hyeon, Roboto, Oswald (전부 Google Fonts)
- 그래픽 리소스(`/api_platform_image/...`) 접근 불가 시 단색 배경으로 fallback

선택 근거: 어차피 레이아웃 데이터가 API에서 제공되므로 추가 비용 대비 시연 임팩트가 크다. 선택지 B는 "내용 목록"이지 "책 프리뷰"가 아니다.

## 결과 (Consequences)

- 긍정적: 시연 시 24페이지 책의 실제 레이아웃을 브라우저에서 확인 가능. 편집 화면에서 실시간 프리뷰 제공
- 부정적: 인쇄 정확도를 보장하지 않음 (프리뷰 ≠ 교정쇄). 그래픽 이미지 fallback으로 일부 시각 요소 누락 가능
- 리스크: SweetBook이 템플릿 레이아웃 스펙을 변경하면 정적 데이터 업데이트 필요

## 되돌릴 조건 (Reversal Triggers)

- SweetBook이 공식 프리뷰 API를 제공할 경우, 자체 렌더러 대신 API 프리뷰로 전환
- 템플릿 레이아웃 좌표와 실제 렌더링 결과의 차이가 커서 오히려 오해를 줄 경우
