# 개발 일지: Foundation Set 1차 기준선 구현

**일자:** 2026-04-04
**관련 버전:** v0.1.0
**관련 역할:** build, ui, spec, ship

## 배경 (Context)

초기에는 `#6~#9`를 화면별 이슈로 바로 구현하려고 했지만, 실제로는 랜딩부터 책 종류 선택까지의 첫 흐름 전체가 동시에 흔들리고 있었다. Stitch 시안도 화면별로는 참고가 됐지만, 제품 전체 리듬과 한국어 톤, 폰트 정책까지 자동으로 맞춰주지는 못했다.

## 문제 (Problem)

`#6 기수 목록 조회 화면 구현` 브랜치에서 작업을 시작했지만, 실제 변경 범위는 대시보드 하나를 넘어서 Foundation Set 5개 화면 전체로 커졌다. 이 상태로 `#6`에 그대로 커밋하면 이슈 범위가 깨지고, 이후 `#7~#9`와의 경계도 모호해지는 문제가 있었다.

## 시도한 것들 (Attempts)

1. **시도 1:** `#6` 범위 안에서 대시보드만 먼저 고정하려고 했다.
   대시보드만 정리하면 될 것처럼 보였지만, 실제로는 랜딩, 기수 상세, 수료생 상세, 책 종류 선택까지 같은 톤과 흐름으로 묶여야 했다.

2. **시도 2:** Stitch 산출물을 그대로 구현 기준으로 삼으려고 했다.
   초반 방향을 잡는 데는 유용했지만, 폰트가 `Pretendard` 기준이 아니고 한국어 카피도 부자연스러운 부분이 있어 실제 코드에서는 디자인 가이드에 맞춘 보정이 필요했다.

3. **시도 3:** Foundation Set를 별도 이슈로 분리했다.
   결과적으로 `#29 Foundation Set 1차 화면 기준선 구현` 이슈를 새로 만들고, 현재 브랜치 범위를 그 이슈로 재귀속하는 방식이 가장 깔끔했다.

## 최종 해결 (Resolution)

Foundation Set 5개 화면을 하나의 기준선 작업으로 묶고, `feat/#29-foundation-set` 브랜치에서 커밋과 PR을 생성했다. 코드 기준으로는 랜딩, 운영자 대시보드, 기수 상세, 수료생 상세, 책 종류 선택, 그리고 API 미기동 시 fallback 동작까지 반영했다.

문서 기준으로는 아래를 함께 고정했다.
- `docs/prd/foundation-set-ui-spec.md`
- `docs/design/foundation-set-design-guide.md`

이로써 이후 `#6~#9`는 새로운 디자인 탐색이 아니라, 이미 반영된 기준선을 화면별로 보정하는 작업으로 좁힐 수 있게 됐다.

## 배운 것 (Lessons Learned)

- 화면별 이슈를 잘게 나눴더라도, 실제 변경 범위가 제품 기준선 수립이라면 별도 이슈로 승격하는 편이 낫다.
- Stitch는 방향을 잡는 데는 좋지만, 한국어 프로젝트에서는 폰트와 카피를 코드 구현 단계에서 다시 다듬어야 한다.
- `1이슈 1브랜치 1PR` 원칙을 지키려면, 범위가 커지는 순간 바로 이슈 구조를 다시 조정해야 한다.
