# 개발 일지: 기수 목록 로딩/빈 상태 구현 (#6)

**일자:** 2026-04-06
**관련 버전:** v0.1.0
**관련 역할:** build, qa

## 배경 (Context)

`#29` Foundation Set 기준선에서 `/dashboard` 페이지는 기수 카드 목록을 렌더링하는 기본 구조가 완성된 상태였다. 그러나 이슈 #6의 DoD에 명시된 "로딩/빈 상태가 처리됩니다" 조건이 미충족 상태였다.

- `loading.tsx`가 없어 Suspense boundary가 없는 상태
- `cohorts.length === 0`일 때 UI가 완전히 비어버리는 문제

## 문제 (Problem)

Next.js App Router에서 async Server Component를 사용하는 경우, 로딩 상태는 `loading.tsx` 파일로 처리하는 것이 공식 패턴이다. 이 파일이 없으면 데이터를 기다리는 동안 사용자에게 빈 화면이 표시된다.

## 시도한 것들 (Attempts)

1. **로딩 상태:** `app/dashboard/loading.tsx` 추가. 기존 카드 레이아웃과 동일한 구조의 스켈레톤 UI. `animate-pulse`로 Tailwind 기본 애니메이션 활용.

2. **빈 상태:** `page.tsx`의 기수 목록 section 상단에 `cohorts.length === 0` 분기 추가. 기존 카드 디자인 언어(rounded-[1.75rem], var(--surface))를 유지한 빈 상태 블록.

## 최종 해결 (Resolution)

- `apps/web/src/app/dashboard/loading.tsx` 신규 작성
- `apps/web/src/app/dashboard/page.tsx` 빈 상태 UI 분기 추가

API fallback 구조(API 불가 시 mock 데이터 반환)가 이미 `api.ts`에 있으므로, 실제로 빈 상태에 도달하는 경로는 매우 제한적이다. 그러나 방어적 처리로 추가하는 것이 옳다.

## QA: Vitest 환경 구성 중 jsdom 충돌

### 문제

`jsdom@29`가 내부적으로 `@asamuzakjp/css-color`의 ESM top-level await를 사용하는데, Vitest의 기본 forks pool이 이를 `require()`로 로드하려다 `ERR_REQUIRE_ASYNC_MODULE` 오류가 발생했다.

### 해결

API/mock-data 유닛 테스트는 DOM이 전혀 필요하지 않다. `vitest.config.ts`의 `environment`를 `'jsdom'`에서 `'node'`로 변경해 jsdom 자체를 로드하지 않도록 수정.

**trade-off:** 향후 컴포넌트 단위 테스트가 필요할 경우, jsdom 대신 `happy-dom`으로 교체하거나 Playwright를 활용한 E2E 테스트로 대체를 권장한다. `jsdom@29`와 Vitest 최신 버전의 조합은 현재(2026-04-06 기준) ESM 호환성 이슈가 있다.

## 배운 것 (Lessons Learned)

- `jsdom` 최신 버전은 Vitest forks pool과 ESM 호환 이슈가 있다. 서버 로직 유닛 테스트는 `environment: 'node'`로 분리하는 것이 안전하다.
- Next.js App Router의 `loading.tsx`는 파일 존재만으로 Suspense boundary를 자동 생성한다. 별도 `<Suspense>` 래핑 불필요.
