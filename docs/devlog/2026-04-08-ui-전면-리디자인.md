# 개발 일지: UI 전면 리디자인 — SweetBook에서 Foliocraft로

**일자:** 2026-04-08
**관련 버전:** v0.1.0
**관련 역할:** ui, build, qa

## 배경 (Context)

Foundation Set 기준선 위에서 구현된 UI의 전체 완성도가 만족스럽지 않아 디자인을 전면 교체하기로 했다. 단순 컬러 변경이 아닌, 프로젝트 이름·폰트·컬러·레이아웃·인터랙션·문서까지 포함하는 전면 리디자인.

## 문제 (Problem)

1. 기존 베이지/브래스 톤이 "부트캠프 수료 포트폴리오 북"이라는 맥락에서 충분한 프리미엄 느낌을 주지 못함
2. 헤드라인 크기, CTA 크기, 섹션 패딩 등이 랜딩페이지 기준에 미달
3. hover/active 피드백이 약해 인터페이스가 정적으로 느껴짐
4. 디자인 문서(토큰/컴포넌트/와이어프레임)가 코드와 동기화되지 않음

## 시도한 것들 (Attempts)

1. **다크 모드 + 코럴 악센트 ("Atelier Noir"):**
   Cormorant Garamond + DM Sans, `#e8553a` 악센트, `#09090b` 배경.
   에디토리얼 느낌은 좋았으나 "인쇄물/책"이라는 서비스 맥락과 다크 모드가 어울리지 않아 폐기.

2. **다크 모드 유지 + 인디고 악센트:**
   사용자 요청으로 악센트를 `#4f46e5`(인디고)로 변경.
   이후 SKILL.md 감사 적용 시 "보라/블루는 AI 디자인 지문"으로 진단되어 폐기.

3. **라이트 모드 + 앰버 악센트 + Outfit 폰트 (최종 채택):**
   SKILL.md 기준으로 체계적 감사 후 적용. `#b45309` 앰버, Outfit 디스플레이 폰트, stone 계열 배경.

## 배운 것 (Lessons Learned)

1. **디자인 변경은 감사 기준을 먼저 세우고 시작해야 한다.** "느낌이 안 좋다"로 시작하면 다크→라이트, 코럴→인디고→앰버처럼 방향이 여러 번 바뀐다. SKILL.md 같은 체계적 감사 체크리스트를 먼저 적용했으면 시행착오를 줄일 수 있었다.

2. **CSS 변수 기반 디자인 토큰은 테마 전환 비용을 극적으로 낮춘다.** 다크→라이트 전환 시 globals.css의 `:root` 변수만 수정하면 대부분 자동 반영. 하드코딩된 컬러(radial gradient의 rgba 값 등)만 수동 수정 필요.

3. **jsdom 29는 ESM 호환 문제가 있다.** Vitest + jsdom 29 조합에서 `ERR_REQUIRE_ASYNC_MODULE` 발생. happy-dom으로 대체하면 즉시 해결. 기존 STATUS.md에 "알려진 이슈"로 등록되어 있었는데, 이번에 실제로 해결.
