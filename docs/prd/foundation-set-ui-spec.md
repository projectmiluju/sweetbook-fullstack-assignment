# [PRD] Foundation Set UI 스펙

**Status:** Draft

**Branch:** feat/#6-cohort-list

## 1. 개요 (Overview)

- **배경 및 목적:** 현재 제품은 `랜딩 → 운영 흐름 → 편집 → 생성/주문`으로 이어지는 멀티스텝 구조다. 부분 화면만 먼저 디자인하면 전체 톤과 정보 구조가 어긋날 가능성이 높다. 따라서 Stitch 작업 전, 제품의 시각 언어와 탐색 리듬을 결정하는 `Foundation Set` 5개 화면을 먼저 고정한다.
- **타겟 워크플로우:** 사용자는 랜딩에서 결과물을 이해하고, 운영자 대시보드에서 기수를 선택한 뒤, 기수 상세와 수료생 상세를 거쳐 책 종류를 선택한다.

## 2. Foundation Set 범위

1. 랜딩페이지
2. 운영자 대시보드
3. 기수 상세 / 수료생 목록
4. 수료생 상세
5. 책 종류 선택

## 3. 공통 디자인 원칙

- 결과물 중심의 서비스이므로, 첫인상은 `운영 도구`보다 `책 결과물`이 먼저 보여야 한다
- 과한 SaaS 블루 톤 대신 `neutral + brass accent` 기반의 차분한 프리미엄 톤을 사용한다
- 모든 화면은 한글 가독성을 우선하며 `word-break: keep-all`을 전제로 한다
- 각 인접 화면은 레이아웃 패턴이 달라야 하지만, 컬러/타이포/표면 질감은 일관돼야 한다
- Hero, 카드, 상태 패널 모두 검은 그림자 대신 배경 색조가 섞인 tinted shadow를 사용한다

## 4. 화면별 명세

### 4.1 랜딩페이지

**1순위 목적**
- 이 서비스가 무엇을 만드는지 빠르게 이해시킨다

**2순위 목적**
- 부트캠프 운영자가 왜 이 서비스를 쓰는지 설명한다

**핵심 메시지**
- 개인 수료 포트폴리오 북이 서비스의 대표 결과물이다
- 이 책은 수료 기념품이면서 동시에 부트캠프 브랜딩 자산이다

**정보 구조**
1. Hero
2. 결과물 소개
3. 왜 필요한가
4. 두 가지 책 종류 소개
5. 운영 흐름
6. 데모 진입 CTA

**Hero 요구사항**
- 주인공은 `개인 수료 포트폴리오 북`
- 실물 책이 펼쳐지는 듯한 연출
- 첫 내지는 `브랜딩된 기념 수료 페이지`
- 다음 장면에 프로젝트 페이지 일부가 보이는 구도 허용
- 메인 카피는 결과물 중심이어야 하며, 운영자 설명은 보조 문단으로 내려간다

**섹션 요구사항**
- 결과물 소개:
  - 책이 실제로 어떤 페이지들로 구성되는지 요약
- 왜 필요한가:
  - `수료 기념품 가치`를 먼저
  - `부트캠프 브랜딩 가치`를 다음
  - `채용/데모데이 공유 가치`는 보조 메시지
- 두 가지 책 종류 소개:
  - 메인 카드: `개인 수료 포트폴리오 북`
  - 보조 카드: `기수 쇼케이스 북`
- 운영 흐름:
  - 기수 선택 → 수료생 선택 → 편집 → 책 생성 → 주문

**주요 CTA**
- `데모 대시보드 보기`

**상태 화면**
- 로딩/빈 상태 없음
- 링크 실패 시 일반 404 또는 내부 이동 실패 처리

**디자인 포인트**
- 완전 대칭형 Hero 금지
- 결과물 비주얼이 가장 먼저 시야를 잡아야 함
- 랜딩 전체는 마케팅 페이지처럼 보여도, 운영 제품과 시각적으로 단절되면 안 됨

### 4.2 운영자 대시보드

**1순위 목적**
- 운영자가 기수를 빠르게 선택한다

**2순위 목적**
- 선택 전에 최소 요약 정보만 비교하게 한다

**핵심 정보**
- 기수명
- 과정명
- 수료 예정일
- 수료생 수

**정보 구조**
1. Hero 또는 상단 안내 영역
2. 기수 카드 그리드
3. 상태 패널 영역

**주요 CTA**
- 기수 카드 전체 클릭
- 에러 상태에서는 `다시 시도`

**상태 화면**
- Loading: 단일 패널
- Empty: 준비된 기수가 없다는 안내
- Error: 다시 시도 버튼 포함

**디자인 포인트**
- 차트형 admin 금지
- 카드 스캔성이 가장 중요
- 첫 카드에만 미세한 강조 변주 허용

### 4.3 기수 상세 / 수료생 목록

**1순위 목적**
- 선택한 기수의 맥락을 보여주고, 수료생 중 누구를 볼지 선택하게 한다

**2순위 목적**
- 다음 단계로 갈 흐름을 자연스럽게 예고한다

**핵심 정보**
- 기수명
- 과정명
- 수료일
- 기수 소개
- 수료생 카드 목록

**정보 구조**
1. 상단 기수 Hero 또는 헤더
2. 기수 요약 패널
3. 수료생 카드 목록
4. 책 종류 선택으로 이어지는 보조 안내

**주요 CTA**
- 수료생 카드 클릭
- `책 종류 선택`은 직접 CTA보다 보조 안내 수준이 적절
- 상단 또는 하단에 `선택한 수료생 기반으로 다음 단계가 이어진다`는 흐름 문구 필요

**상태 화면**
- Loading
- Empty: 수료생 없음
- Error: 목록 재시도
- 잘못된 기수 ID 접근 시 404

**디자인 포인트**
- 운영자 대시보드보다 정보 밀도는 올라가지만, 아직 편집 화면처럼 복잡하면 안 됨
- 카드 목록은 균등 그리드보다 리듬감 있는 리스트/카드 혼합이 적합할 수 있음

### 4.4 수료생 상세

**1순위 목적**
- 책으로 만들기 전, 수료생의 원본 콘텐츠를 충분히 검토하게 한다

**2순위 목적**
- 이 데이터가 책으로 어떻게 번역될지 기대감을 준다

**핵심 정보**
- 자기소개
- 브랜딩된 기념 수료 페이지 정보
- 기술 스택
- 대표 프로젝트
- 회고
- 멘토 코멘트
- 활동 사진

**정보 구조**
1. 수료생 헤더
2. 핵심 프로필 요약
3. 프로젝트 섹션
4. 회고 / 멘토 코멘트 섹션
5. 사진 섹션
6. 책 종류 선택 또는 책 만들기 진입 CTA

**주요 CTA**
- `책 종류 선택하기`

**상태 화면**
- Loading
- Error
- 잘못된 수료생 ID 접근 시 404
- 일부 데이터 누락 시 fallback 텍스트 허용

**복귀 흐름**
- 기본 복귀 링크는 `대시보드`가 아니라 `직전 기수 상세`여야 한다
- 즉, 수료생 상세는 항상 자신이 속한 기수 맥락을 유지해야 한다

**디자인 포인트**
- 단순 프로필 페이지보다 `에디토리얼 프리뷰` 성격이 느껴져야 한다
- 프로젝트와 회고는 같은 카드 패턴 반복을 피하고, 다른 밀도의 레이아웃을 섞는다

### 4.5 책 종류 선택

**1순위 목적**
- 운영자가 `개인 북`과 `기수 쇼케이스 북` 중 하나를 명확히 고르게 한다

**2순위 목적**
- 두 결과물의 차이와 활용 목적을 혼동 없이 이해시키는 것

**핵심 정보**
- 현재 선택한 대상 정보
  - 개인 북: 수료생 이름, 소속 기수
  - 기수 쇼케이스 북: 기수명, 수료생 수
- 각 책 종류의 목적
- 포함 콘텐츠
- 대상
- 활용 장면

**정보 구조**
1. 상단 선택 안내 영역
2. 현재 선택 대상 컨텍스트 패널
3. 2개 선택 카드
4. 보조 비교 정보
5. 다음 단계 진입 CTA

**주요 CTA**
- `개인 수료 포트폴리오 북 선택`
- `기수 쇼케이스 북 선택`
- 두 CTA는 실제 다음 단계로 이어져야 하며, `대시보드로 복귀`로 끝나면 안 된다

**상태 화면**
- 별도 로딩 없음
- 대상 데이터가 없을 경우 이전 단계로 복귀 유도

**디자인 포인트**
- 두 카드의 계층은 명확히 다르되, 과하게 경쟁시키지 않는다
- 개인 북은 메인 상품, 기수 쇼케이스 북은 확장 옵션으로 보이게 한다
- 이 화면은 카탈로그가 아니라 `선택 단계`이므로, 현재 누구/무엇을 책으로 만들고 있는지 항상 보여야 한다

## 5. 화면 간 사용자 플로우

1. 랜딩페이지에서 결과물을 이해한다
2. `데모 대시보드 보기`로 운영자 대시보드에 진입한다
3. 기수를 선택해 기수 상세 / 수료생 목록으로 이동한다
4. 수료생 상세에서 원본 콘텐츠를 검토한다
5. 책 종류 선택에서 현재 선택 대상을 확인한다
6. `개인 북` 또는 `기수 쇼케이스 북`을 선택한다
7. 다음 단계는 편집 또는 미리보기로 이어진다

## 6. 예외 처리 정책

| 상황 | 대응 방안 | 우선순위 |
|------|---------|---------|
| 기수 데이터 0건 | 대시보드/기수 상세에서 빈 상태 패널 제공 | 높음 |
| 잘못된 기수 ID 접근 | 404 또는 목록 복귀 유도 | 높음 |
| 잘못된 수료생 ID 접근 | 404 또는 이전 단계 복귀 유도 | 높음 |
| 상세 데이터 일부 누락 | fallback 텍스트와 숨김 처리로 레이아웃 붕괴 방지 | 높음 |
| 네트워크/서버 에러 | 재시도 버튼과 일반화된 오류 문구 제공 | 높음 |
| 책 종류 선택 진입 시 대상 정보 없음 | 이전 단계로 복귀 유도, 잘못된 접근 안내 | 높음 |
| 백엔드 미기동 | 더미 데이터 fallback 허용, 단 명시적 에러 상태 설계는 별도 유지 | 중간 |

## 7. 현재 구현 대비 필수 수정 사항

### 7.1 랜딩페이지
- `결과물 소개 또는 신뢰 섹션`은 3열 균등 카드 나열로 처리하지 않는다
- 같은 높이의 단순 정보 카드 3개 대신, `metrics strip`, `bento`, `zig-zag` 중 하나로 재구성한다
- Hero 이후 첫 섹션은 랜딩의 리듬을 만드는 역할이어야 하며, 평범한 SaaS 소개 블록처럼 보이면 안 된다

### 7.2 운영자 대시보드
- 현재 fallback이 있더라도 `Loading / Empty / Error` 상태 스펙은 화면 구조상 유지되어야 한다
- 추후 구현 이슈에서 재시도 액션과 빈 상태 패널을 반드시 드러내야 한다

### 7.3 기수 상세 / 수료생 상세
- 수료생 상세의 복귀 링크는 `기수 상세` 기준으로 재설계한다
- 기수 상세는 다음 단계가 `수료생 선택 → 책 종류 선택`으로 이어진다는 문맥을 더 분명히 보여야 한다

### 7.4 책 종류 선택
- 이 화면은 정보 카드 비교로 끝나면 안 된다
- 현재 선택 대상(`수료생` 또는 `기수`)이 명시되어야 한다
- 두 CTA는 편집/미리보기 등 실제 다음 단계로 이어져야 한다
- `대시보드로 돌아가기` 중심 구조는 요구사항과 맞지 않으므로 수정 대상이다

- `$ui` 또는 Stitch 작업은 이 문서를 기준으로 Foundation Set 5개 화면의 시안을 생성한다

## 11. 가정 (Assumptions)

- 랜딩페이지의 1순위 목적은 `서비스 이해`라고 본다
- 랜딩 Hero의 주인공은 `개인 수료 포트폴리오 북`이다
- `기수 쇼케이스 북`은 메인 Hero보다 하위 섹션에서 보조적으로 소개한다
- Foundation Set이 전체 제품 시각 언어를 결정한다고 가정한다
